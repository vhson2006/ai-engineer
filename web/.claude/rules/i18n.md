# Languages (i18n)

Decision and alternatives: ADR 0020. Sub-path routing (`/en/about`, `/vi/about`), one JSON
dictionary per language, no i18n library.

- **No user-visible text in code.** Every string a visitor reads (labels, buttons, errors,
  `aria-label`, `<title>`, placeholders) comes from `src/i18n/messages/<lang>.json`. Add the key
  to EVERY language in the same change; `en.json` is the reference shape. Technical values that
  aren't language (product names, code, roles like `deployment:read`) may stay literal.
- **Pages live under `app/[lang]/`**; Route Handlers that aren't pages (`/auth/*`, `/files/*`)
  stay outside and are listed in `ROUTING.bypass` (`src/i18n/locales.ts`).
- **Server Components read the dictionary with `getMessages()` / `getLocale()`**
  (`src/i18n/messages.ts`, via `next/root-params`): no `lang` prop drilling. Client Components
  never import a dictionary: the server passes them the strings they need as props.
- **Every internal link is localized**: `href(locale, '/about')`, never a bare `'/about'` (that
  costs a redirect, and loses the language for visitors without the cookie). Forms too
  (`action={href(locale, '/dashboard')}`), and `returnTo` values.
- **Placeholders**: `format(t.x, { name })` (`@web/core/i18n/format`); React content inside a
  sentence: `richText(t.x, { name: <strong/> })` (`@web/ui`), so each language keeps its word order.
  Counts: `plural(locale, n, { one, other })`. Dates and numbers: `Intl.*` with
  `LOCALES[locale].intl`, never a hard-coded `'en-GB'`.
- **Metadata** is per language: `generateMetadata()` reading `getMessages()`, not a static `metadata`.
- **The proxy** redirects page paths without a locale (cookie → `Accept-Language` → the app's
  `defaultLocale`) and saves the language of a visited page; only GET/HEAD are redirected; prefetches
  don't change the saved language. Keep `routeLocale` + `rememberLocale(…, ROUTING)` in every app's proxy.
  Public sites set `detectLanguage: false` (a first visit lands on the default: VI for portfolio,
  laundry, wine and the sample sites; EN for nails) and the business sites their own `cookieName`
  (dev: all on localhost); portfolio and admin keep `NEXT_LOCALE` (read by `/auth/*`).
- **Business sites** (`@web/site-kit`): languages, their order, default and Intl locales are
  `defineWebsite` options (`src/website.ts`; routing = `website.routing`, dates and hours =
  `website.instantDate` / `website.hours`); the kit's strings are merged with the site's
  (`mergeMessages`, `src/i18n/dictionaries.ts`). A new language: the kit's `LOCALES` and dictionary
  first, then each site's dictionary and `locales`.
- **A new language**: `messages/<code>.json` + one line in `LOCALES` + one loader in
  `messages.ts` + the map in `messages.test.ts`. The Keycloak login page follows through
  `ui_locales` only if the realm offers that language.
- Tests: `messages.test.ts` (same keys, no empty strings, same `{placeholders}` in every
  language), `packages/core/src/i18n/i18n.test.ts` (negotiation, redirects, cookie).
