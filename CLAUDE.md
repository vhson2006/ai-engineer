## System non-negotiables

1. **The API is private** (ADR 0003): only the web apps' servers call KrakenD; nothing in the
   browser talks to the API.
2. **Tokens never reach the browser** (ADR 0010): httpOnly session-id cookie, tokens sealed in Redis.
3. **Every route is authenticated twice** (ADR 0002): KrakenD and the service's `AuthGuard`,
   same roles; data rules (owner, site) in the service.
4. **Admin surfaces are never public** (ADR 0004), except the admin SITE `admin.*` (ADRs 0019,
   0030): admins only (site admins: password; superadmins: password + OTP), role re-checked by the app.
5. **File bytes go straight between browser and storage** (ADRs 0006, 0014); the one exception:
   images generated by ai-service, which writes them itself (ADR 0037).
6. **A change is complete across every part it touches**: a new or changed endpoint = contract
   (`libs/common`) + service route + KrakenD endpoint (incl. forwarded params/headers) + web
   helper (`web/packages/core/src/api/<resource>.ts`) + tests on both sides.

## Where things go

- One package's agent rules → its `CLAUDE.md` (short, always loaded) and `.claude/rules/*.md`
  (details, by `paths:`); procedures → `.claude/skills/`. System-wide and `k8s/` → root files.
- How to run → READMEs. Review checklists → each package's `docs/ai/code-review.md`; AI policy →
  `docs/ai/ai-usage-policy.md`. Decisions → `docs/adr/` (an ADR in the same change; a reversal
  is a new ADR, the old one marked `Superseded by NNNN`).
- **Each rule lives in one place; elsewhere, link to it.** Paths in root docs are relative to the
  root; in package docs relative to the package, except `k8s/...`, `docs/adr/...`, root `.claude/...`.

## Commands (repo root)

```bash
npm run k8s:up && npm run k8s:forward   # local stack (overlays/dev); keep the forward open
npm run k8s:render                      # / k8s:render:prod, without applying
npm run krakend:check
npm run keycloak:admin-url && npm run keycloak:admin-otp   # once per fresh cluster / namespace
npm run staging:build && npm run staging:up                # prod images locally, HTTPS (ADR 0018)
```
API: `cd nest-microservice && npm run start:dev`. Web: `cd web && npm run dev` (admin: alice + dev
OTP, `web/apps/admin-web/README.md`).

## CI

`ci.yml` runs per changed part the package commands (api: lint, format, test, integration, build; web:
`check`; k8s: render every overlay + `krakend-check.sh`); required check `ci-ok`. A new package or
check goes into it in the same change. `images.yml` builds changed images to GHCR and commits
their `newTag` in `k8s/overlays/prod/kustomization.yaml`: never edit those lines by hand; a new
image = a matrix entry + an `images:` entry with `newTag: placeholder` (never another image's sha:
the next run builds it and writes the real tag).

If a convention changes, update this file, the package files and the rules in the same change.
